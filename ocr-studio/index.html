Cham OCR Studio is an open-source, specialized paleographic transcription and diagnostic platform engineered specifically for the digitized preservation and optical character recognition of historical Cham manuscripts (comprising traditional Akhar Thrah of Eastern Cham and Cam Srak of Western Cham).

📜 Paleographic & Orthographic Characteristics

The Cham script belongs to the Brahmic family of Southern Indic scripts (descended historically from the Grantha and Pallava writing systems of ancient Champa). As an abugida, its visual and computational representation poses significant challenges:

  • Independent Vowels & Consonants: The Unicode Cham block (U+AA00–U+AA5F) specifies 6 independent vowels (U+AA00–U+AA05: A, I, U, E, AI, O) and 35 consonants (U+AA06–U+AA28) possessing an inherent vowel (/a/ or /ɔ/), structured into low-tone (Dom) and high-tone (Dal) series.
  • Subjoined Medials (Pang Ka-ak): Four medial signs attach beneath or wrap around initial consonants: ꨳ (U+AA33: Medial Ya), ꨴ (U+AA34: Medial Ra), ꨵ (U+AA35: Medial La), and ꨶ (U+AA36: Medial Wa).
  • Multi-Directional Dependent Vowels: Vowel diacritics occupy positions above (ꨪ, ꨫ, ꨬ), below (ꨭ U, ꨲ UE), post-base right (ꨩ AA, ꨮ OE, ꨱ AU), or pre-base left (ꨯ O, ꨰ AI).
  • Final Consonants & Signs ([U+AA40–U+AA4D, U+AA25]): Explicit codas with extended terminal strokes, combining coda marks (ꩃ Final Ng, ꩌ Final M, ꩍ Final H), and base consonant ꨥ (U+AA25: VA) serving as syllable-final consonant per Unicode Table 16-16.
  • Scriptio Continua & Punctuation: Classical manuscripts predominantly omit whitespace between words, demarcating syntax via Danda (꩝ U+AA5D), Double Danda (꩞ U+AA5E), or Triple Danda (꩟ U+AA5F). Modern printed Cham publications frequently introduce word-level spacing.
🔤 Canonical Unicode & Logical Order Standardization

Encoded in Unicode Standard 5.1 within the range U+AA00–U+AA5F, Cham text processing requires strict differentiation between visual rendering order and Brahmic Logical Order. The canonical storage sequence enforced in Cham OCR Studio is:

Base Consonant + Medials (Ya/Ra/La/Wa) + Pre-Vowels (O/AI) + Dependent Vowels + Vowel Lengthener AA + Final Consonants / Signs (incl. Final VA)
🔍 Dual-Stage Hybrid Segmentation Pipeline

Historical palm-leaf and handmade paper manuscripts frequently exhibit undulating line trajectories, uneven inter-line spacing, and ink bleed-through. Cham OCR Studio employs a two-tier hybrid segmentation architecture:

Stage 1: Fine-Tuned DBNet (Differentiable Binarization Network)

Operates with an adaptive unclip ratio of 1.8. DBNet predicts a continuous probability map and adaptive threshold surface, outputting polygon boundaries that conform snugly to curvilinear text baselines while encompassing ascenders and descenders.

Stage 2: Indic Valley-Cut Heuristic Engine (Fallback)

When deep detection yields ambiguous boundaries, a horizontal projection profile is generated across adaptive sliding windows. Valleys in projection intensity indicate candidate baseline cutpoints, combined with Connected Component Analysis (CCA) to prevent cutting across intersecting glyph stems.

🛡️ Boundary Safeguards & Stroke Protection
  • Connected Component Exclusion (difference_update): When establishing an erasing mask for neighboring lines, components belonging to the current textline are strictly excluded, eliminating stroke truncation.
  • Safe Vertical Padding Safeguards: Every line crop is guaranteed a minimum buffer of 0.40 × median_line_height above and below the core band, clipped at 2px from adjacent textbands.
  • Legacy-First / No-Change Gate: Clean manuscript folios with line pitch gap ≥ 0.35 × median_line_height and initial recognition confidence ≥ 0.75 bypass multi-pass deformation to prevent regression.
🧠 Neural Recognition: PP-OCRv4 SVTR-LCNet

The recognition engine leverages a customized SVTR-LCNet backbone optimized for high-density historical scripts:

  • Depthwise Separable Convolutions: Maximizes representation capacity while sustaining lightweight inference speeds on commodity CPU hardware.
  • Squeeze-and-Excitation (SE) Attention: Dynamically recalibrates channel-wise feature responses, emphasizing delicate diacritic strokes against noisy paper backgrounds.
  • Expanded Input Geometry: Receptive dimension configured to [3, 48, 480] (expanded from 320px) to prevent spatial compression of dense character clusters and bilingual verses.
🎯 Joint CTC & NRTR Auxiliary Decoding

Sequence prediction employs dual-head multi-task learning:

  • Connectionist Temporal Classification (CTC) Head: Computes alignment-free token probabilities with forward-backward dynamic programming, optimizing real-time throughput.
  • NRTR Cross-Attention Auxiliary Head: Utilizes multi-head self-attention transformer blocks during training to penalize character omissions on ambiguous minimal pairs.
⚙️ Post-OCR Canonical Unicode Cluster Normalization

To resolve local model hallucinations where visual rendering order flips adjacent diacritics, the system applies an algorithmic Unicode cluster re-ordering stage (normalize_unicode):

Input Artifact: ꨙ (Nda) + ꨯ (Vowel O) + ꨳ (Medial Ya) + ꨮ (Vowel Oe) Canonical Brahmic Cluster: ꨙ (Nda) + ꨳ (Medial Ya) + ꨯ (Vowel O) + ꨮ (Vowel Oe)

⚡ Dynamic In-RAM Augmentation & Training Safeguards
  • Zero-Baked-Blur Policy: Clean textlines are rendered to disk. Photometric noise, Gaussian defocus, and directional motion blur (kernels 7×7 to 13×13, θ ∈ [0°, 180°]) are applied dynamically in RAM (35% probability) during batch loading.
  • Font CMAP Tofu Filtering: fontTools inspects character maps before generation, discarding unsupported glyphs to prevent square placeholder (tofu) corruptions.
  • Character-Mapped Weight Surgery (surgery_v25_weights.py): Re-maps neural projection heads across expanding lexicons without shape mismatch.
  • Distributed Multi-GPU Architecture: Trained on Kaggle Nvidia Tesla T4x2 (DDP) and Lightning Cloud A100 SXM4 using AMP O1 mixed precision with 3-stage checkpoint resilience.

3. Model Classification: V25 Validated SOTA vs V24 Logical Baseline

Evaluation across 10,000 frozen validation samples establishes Version 25 as the new production SOTA model (Sequence Accuracy 90.96%, Normalized Edit Distance 99.28%, CER 0.72%) following 40 epochs of multi-stage training on Dual Tesla T4x2 GPUs. Version 24 serves as the logical order baseline (Accuracy 88.94%), while Version 23 is maintained for legacy visual order comparison.

🔍 Error Metrics Definition

Character Error Rate (CER) computed as normalized Levenshtein edit distance: CER = (Substitutions + Deletions + Insertions) / Total Ground-Truth Characters.

🚀 Cloud Serving & Microservice Architecture

Cham OCR Studio is architected for zero-latency, high-availability public access:

Containerized Microservice (Docker)

Packaged via a multi-stage Docker container deployed directly on Hugging Face Spaces (phucsd/cham-ocr-studio) and routed through Cloudflare to the official production domain: https://ocr.cham.asia.

🛡️ Runtime Concurrency & Thread Isolation
  • OpenMP & MKL Deadlock Safeguards: Multi-threaded OpenMP and OneDNN execution are explicitly pinned to single-thread mode inside HTTP socket worker threads to eliminate deadlock states on CPU runtimes.
  • NumPy 2.x Compatibility Patch: Automated runtime monkeypatching for legacy np.sctypes, np.bool, and np.typeDict ensuring seamless operation under modern Python 3.13+ environments.
  • Client-Side IndexedDB Storage: Manuscript queues and multi-megabyte folios persist locally in client browser storage, minimizing network payloads and server compute strain.
